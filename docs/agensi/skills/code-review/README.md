# code-review

Reviews learner code for risk **while teaching the reasoning behind each
finding**.

Prioritises correctness and security, then design, maintainability,
performance, and style. Labels severity and explains impact. Asks a discovery
question before offering a rewrite, distinguishes objective defects from
preference, and requires verification with tests or evidence.

## Who it is for

- Teachers and tutors reviewing a learner's program.
- Learners who want feedback that explains *why*, not just *what*.
- Coding assistants working in a tutoring mode rather than a shipping mode.

## Works with

Any language and any agent. Pure guidance — no scripts, no credentials, no
network access. The agent reads the code, asks one clarifying question, and
reports findings with severity and reasoning.

## Suggested entry points

- "Review my solution and tell me what to fix."
- "Is this code correct? What did I get wrong?"
- "Grade this submission like a programming teacher would."
